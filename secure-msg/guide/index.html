봉인 상태 정상 ✔

한 줄로

봉인 스티커를 메신저로 만들었습니다

노트북 상자에 붙은 "떼면 VOID 글자가 남는 스티커"를 떠올려 보세요. 스티커는 상자를 못 열게 막지 못합니다. 대신 누가 열었다면 반드시 흔적을 남깁니다.

덜미도 같은 생각에서 출발합니다. 메시지를 중계하는 서버는 마음만 먹으면 메시지를 바꾸거나, 대화 중간에 끼어들거나, 남의 이름으로 가짜 메시지를 보낼 수 있는 위치에 있습니다. 덜미는 서버를 믿지 않습니다. 서버가 그런 짓을 하면 사용자 화면에 경고가 뜨게 만듭니다. 그리고 정말 중요한 비밀은 두 사람이 함께 있어야만 열리는 금고에 넣습니다.

장면으로 이해하기

동아리 회계 인수인계

졸업하는 회계 A가 동아리 통장 비밀번호를 신임 회계 B에게 넘겨야 합니다. 그런데 B 혼자 마음대로 보면 곤란해서, 회장 C가 확인해 줘야 열리게 하고 싶습니다.

1

A가 금고에 맡긴다

비밀번호를 금고에 넣고 열쇠를 반으로 쪼개 B와 C에게 하나씩 줍니다. A의 노트북에서는 지웁니다.

A> /lock B C "통장 비번" 4512
2

서버는 내용을 모른다

서버는 봉인된 반쪽 열쇠 두 개와 알아볼 수 없는 글자만 지나보냅니다. 아무것도 보관하지 않습니다.

서버 눈: 8e 1f 0a 77 c2 d9 …
3

B 혼자서는 못 연다

며칠 뒤 B가 열려고 하면 C에게 승인 요청이 갑니다. 반쪽 열쇠 하나로는 아무것도 알 수 없습니다.

B> /open 통장 [*] C의 승인을 기다리는 중
4

C가 승인하면 열리고, 증명이 남는다

C가 자기 반쪽을 B에게만 넘깁니다. 모두의 화면에 누가 언제 누구 승인으로 열었는지 도장 찍힌 기록이 뜹니다.

[증명] C가 B에게 '통장 비번' 열쇠를 넘김 · 21:03 ✔

먼저 알아 둘 말 여섯 개

이 정도만 알면 끝까지 읽힙니다

암호화 encryption
열쇠가 있어야 풀리는 글자로 바꾸는 것. 자물쇠 달린 상자에 넣는 것과 같습니다.
서버 server
메시지를 받아서 상대에게 넘겨 주는 컴퓨터. 덜미에서는 우체부 역할만 하고, 우리는 우체부를 믿지 않습니다.
공개키와 개인키
둘이 한 쌍인 열쇠. 공개키는 누구나 넣을 수 있는 우체통 투입구, 개인키는 우체통을 여는 주인만의 열쇠입니다.
해시 hash
어떤 데이터든 짧은 "지문"으로 바꾸는 계산. 같은 입력은 늘 같은 지문, 지문으로 원래 데이터를 되돌릴 수는 없습니다.
서명 signature
디지털 인감 도장. 개인키로만 찍을 수 있고, 누구나 공개키로 진짜 도장인지 확인할 수 있습니다.
종단간 암호화 E2E
보내는 사람 노트북에서 잠그고 받는 사람 노트북에서만 푸는 것. 중간의 서버는 잠긴 상자만 봅니다.

기본 · 종단간 암호화

서버 눈에는 이렇게 보입니다

A와 B는 처음 만날 때 공개키를 주고받아서, 둘만 아는 열쇠를 각자 계산해 냅니다. 열쇠 자체는 네트워크로 보내지 않습니다. 그 열쇠로 잠근 메시지만 서버를 지나갑니다.

열쇠는 두 사람마다 따로 있습니다. 그래서 대화 방식이 두 가지입니다. 그냥 입력하면 전체 대화가 되어, 접속한 사람마다 각자의 열쇠로 따로 잠가 보냅니다. /dm B를 치면 1:1 대화가 되어 B와의 열쇠로 잠근 메시지가 B 한 명에게만 갑니다. /all을 치면 다시 전체 대화로 돌아옵니다. 두 사람만 접속하면 그대로 1:1 메신저입니다.

기본 · 메시지마다 바뀌는 열쇠

한 번 쓴 열쇠는 바로 버립니다

메시지를 하나 보낼 때마다 지금 열쇠를 해시해서 다음 열쇠를 만들고, 쓴 열쇠는 지웁니다. 해시는 거꾸로 계산할 수 없으니, 나중에 누가 지금 열쇠를 훔쳐도 지난 메시지는 열지 못합니다. 이것을 래칫(ratchet, 한쪽으로만 도는 톱니)이라고 부릅니다.

실습 · 래칫브라우저의 SHA-256으로 실제 열쇠를 만듭니다

정직하게 말하면, 지금 열쇠를 훔친 사람은 다음 열쇠는 계산할 수 있습니다. 덜미가 지키는 건 지난 대화입니다.

핵심 · 한글 단어 지문

서로의 단어 여덟 개를 소리 내어 맞춰 봅니다

서버가 처음부터 끼어들어서 A에게는 "내가 B야", B에게는 "내가 A야" 하고 자기 공개키를 내밀면 어떻게 될까요. 이걸 중간자 공격이라고 합니다. 막는 방법은 하나입니다. 상대의 공개키가 정말 그 사람 것인지 서버 바깥에서 확인하는 것입니다.

덜미는 각자의 공개키 지문을 한글 단어 8개로 보여 줍니다. 같은 방에서 "호랑이, 연필, 바다…" 하고 읽어 보면 됩니다. 단어 하나가 8비트라서 8개면 64비트입니다. 서버가 같은 단어가 나오는 가짜 열쇠를 찾으려면 수천만 년쯤 계산해야 합니다. 숫자 12자리를 쓰던 처음 설계는 몇 분이면 뚫렸습니다.

실습 · 단어 지문실습은 단어 64개로 간단히 했습니다. 실제 프로그램은 팀이 고른 256개를 씁니다

핵심 · 두 열쇠 금고

반쪽 열쇠로는 아무것도 알 수 없습니다

금고의 원리는 생각보다 단순합니다. 비밀과 같은 길이의 완전한 무작위 값 S1을 만들고, 비밀과 S1을 XOR(비트를 하나씩 비교해 같으면 0, 다르면 1)한 값을 S2로 둡니다. S1과 S2를 다시 XOR하면 비밀이 나옵니다. S1이 완전히 무작위라서 S2 하나만 봐도, S1 하나만 봐도 비밀에 대해 알 수 있는 게 전혀 없습니다.

핵심 · 공격 실험실

이제 당신이 서버입니다

발표 날 교수님께 서버 키보드를 넘겨 드릴 장면을 미리 해 봅니다. A로 메시지를 보내고, 가운데 서버 화면의 공격 버튼을 눌러 보세요. B 화면에 무엇이 뜨는지 보면 됩니다.

실습 · 공격 실험실암호화는 브라우저의 AES-GCM입니다. 실제 프로그램은 같은 종류(인증 암호)의 XChaCha20-Poly1305를 씁니다

다른 프로그램과 무엇이 다른가

"시중에 이미 있지 않나요?"에 대한 답

종단간 암호화나 메시지마다 바뀌는 열쇠는 Signal 같은 메신저에 이미 있습니다. 덜미는 그걸로 경쟁하지 않습니다. 비교해 보면 빈자리가 보입니다.

기업용 금고는 승인을 받아야 비밀을 보여 주지만, 원문은 금고 서버가 갖고 있어서 서버 관리자는 볼 수 있습니다. 덜미는 서버에게 볼 능력 자체가 없습니다. "서버가 배신해도 못 엶"은 단어 지문을 한 번 맞춰 둔 경우의 이야기입니다(조사 시점 2026년 10월).

C를 몰라도 되는 C 이야기

프로그램은 이렇게 나뉘어 있습니다

덜미는 C 언어로 만든 프로그램 두 개입니다. 대화하는 사람마다 켜는 client와, 한 대에서만 켜는 server. 노트북끼리만으로 충분하고 서버 전용 컴퓨터는 필요 없습니다.

소켓
두 프로그램 사이에 놓는 전화선. 한쪽이 바이트를 넣으면 반대쪽으로 나옵니다.
패킷
전화선으로 보내는 봉투. 바이트가 줄줄이 이어 오기 때문에 봉투 맨 앞에 길이를 적어 어디까지가 한 통인지 알게 합니다.
poll
전화기 여러 대를 한꺼번에 지켜보다가 울리는 것만 받는 교환원. 서버 하나가 여러 사람을 동시에 상대하는 방법입니다.
libsodium
전 세계에서 검증된 암호 부품 상자. 자물쇠를 직접 깎으면 거의 반드시 구멍이 생겨서, 부품은 빌려 쓰고 조립을 우리가 합니다.

우리가 직접 짜는 것

  • 봉투(패킷) 모양과 길이 적기
  • 여러 사람을 동시에 받는 중계 서버
  • 순서번호 검사와 경고 화면
  • 열쇠를 XOR로 반 나누기와 금고 흐름 전체
  • 한글 단어 지문과 열쇠 바뀜 경보
  • 공격 실험실의 공격 명령들

libsodium에서 빌려 쓰는 것

  • 공개키 만들기와 열쇠 맞추기 (X25519)
  • 인증 암호 (XChaCha20-Poly1305)
  • 해시 (BLAKE2b)와 서명 (Ed25519)
  • 받는 사람만 여는 봉인 (sealed box)
  • 안전한 난수

정직하게

덜미가 못 하는 것

과장은 질문 하나에 무너집니다. 그래서 한계를 먼저 적어 둡니다.

  • 단어를 맞추기 전에는 모든 보호가 서버 앞에서 무력합니다. 처음 만났을 때 한 번은 꼭 소리 내어 확인해야 합니다.
  • 지금 열쇠가 새면 지난 메시지는 안전하지만, 그 뒤 메시지는 열립니다.
  • 금고에서 연 내용을 B가 베껴 적거나 화면을 찍는 건 막지 못합니다. 증명할 수 있는 것은 "C가 B에게 열쇠를 넘겼다"까지입니다.
  • 금고를 맡긴 A는 원래 내용을 압니다. 금고가 막는 건 받는 사람 한 명이나 서버가 혼자 여는 것입니다.
  • 누가 누구에게, 언제, 얼마나 보냈는지는 서버가 봅니다. 1:1 대화도 내용은 숨기지만 누구와 1:1로 대화하는지는 서버가 압니다.
  • 같은 Wi-Fi 안의 노트북끼리만 연결되고, 접속해 있지 않은 사람에게는 보낼 수 없습니다.
