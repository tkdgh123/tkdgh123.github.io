01무엇을 지키나

덜미는 중계하는 쪽(서버·방장)을 믿지 않는 것에서 출발한다. 모든 글이 중계를 거치니까, 중계는 마음만 먹으면 아래 일을 다 할 수 있는 자리에 있다.

중계가 하려는 것지금 (평문)암호화 뒤
엿보기 — 글을 읽음그대로 보임암호문만 보임
바꾸기 — 글자 하나를 고쳐 넘김아무도 모름받는 쪽 경고 · 버림
다시 보내기 — 지난 글을 또 넘김아무도 모름받는 쪽 경고 · 버림

02왜 종단간 암호화인가 — https 방식으로는 안 되는 이유

웹사이트의 https(TLS)는 나와 서버 사이만 잠근다. 서버에 도착하면 풀린다. 덜미에 그걸 쓰면 수빈→서버 구간, 서버→민지 구간은 잠기지만, 가운데 서버는 다 읽는다. 우리가 못 믿는 게 바로 그 서버라서 소용없다.

그래서 보내는 사람이 잠그고, 받는 사람만 푼다(종단간). 카카오톡 비밀채팅·Signal과 같은 생각이다. 중계 코드(③ 칸)는 내용을 몰라도 받을 사람 칸만 보고 넘기면 되니 거의 안 바뀐다.

암호 알고리즘 자체를 직접 짜면 작은 실수 하나가 그대로 구멍이 된다. 그래서 알고리즘은 검증된 C 라이브러리 libsodium에 맡기고, 우리는 조립과 규칙(열쇠를 언제 만들고, 무엇에 도장을 찍고, 받을 때 무엇을 검사하는지)을 짠다.

06단어 지문 — 만나서 맞춰 보기

신원 공개키를 해시한 앞 8바이트를 단어 256개 표에 하나씩 대응시켜 한글 단어 8개로 바꾼다. 같은 키면 실행할 때마다 같은 단어다. 처음 만난 사람과는 옆에서(또는 전화로) 서로의 단어를 소리 내어 읽고 맞으면 확인 표시를 한다.

# 현우 화면 — 처음 만남 (단어는 예시)
[열쇠] 민지 처음 만남 · 단어 고래-라면-등대-노을-탁구-혜성-냄비-참새 · 만나서 맞춰 보고 /verify 민지 ok
현우> /verify 민지 ok
[열쇠] 민지 ✔ 확인한 열쇠로 기억합니다
# 다음에 다시 접속했을 때 — 같은 키
[열쇠] 민지 ✔ 전에 단어를 확인한 열쇠
# 누가 중간에 끼어들어 키가 바뀌었을 때
[!] 민지의 열쇠가 바뀜: 고래-라면-… → 사막-연필-…
    민지에게 단어를 소리 내어 다시 읽어 달라고 하세요 (/verify 민지)
  • 확인한 키는 ~/.deolmi/이름/known에 "이름 · 신원 공개키 · 확인했나"로 적어 둔다. 처음 한 번만 맞춰 보면 된다.
  • 왜 단어 8개인가 — 처음엔 숫자 12자리(40비트)였다. 40비트(약 1조 가지)는 끼어드는 쪽이 키를 계속 만들어 보며 같은 지문을 찾기에 짧다 — 그래픽카드면 몇 시간 거리다. 단어 8개는 64비트라 그보다 약 1,600만 배 어렵고, 숫자보다 읽어 주기 쉽다.
  • Signal의 "안전 번호"와 같은 장치다.

07메시지 잠그기 — 한 통마다 바뀌는 열쇠

두 사람이 HELLO를 주고받으면 kx_chains가 방향별 시작 열쇠 CK₁을 만든다 (나→너, 너→나 따로). 보낼 때마다 이 열쇠를 한 칸씩 앞으로 돌린다(래칫 — 한 방향으로만 돌아가는 톱니).

── 보낼 때 (n번째) ──
MK_n   = BLAKE2b(키 = CK_n, 내용 = "msg")              이 한 통만 잠그는 열쇠
암호문 = XChaCha20-Poly1305(MK_n, 평문_n, nonce, AD)  AD = 헤더의 종류·보낸 사람·받을 사람·seq
CK_n+1 = BLAKE2b(키 = CK_n, 내용 = "next" ‖ 평문_n)    방금 보낸 문장을 섞어 다음 열쇠
CK_n, MK_n 지움                                        열쇠는 보내지 않는다
── 받을 때 ──
같은 식으로 MK_n 계산 → 풀어 봄 → 성공했을 때만 CK_n+1로 전진
헤더 칸지금암호화 뒤
seq01, 2, 3 … 두 사람 사이 방향마다 따로 센다
nonce0매번 새로 뽑은 무작위 24바이트
본문0/1 + 글(0/1 + 글)을 잠근 암호문 + 태그 16바이트
종류·보낸 사람·받을 사람그대로그대로 보이지만 AD로 묶여서, 중계가 바꾸면 풀리지 않는다
  • 지난 대화는 안전 — 옛 CK는 덮어써서 지운다. 지금 체인 열쇠가 새어도 해시를 거꾸로 돌릴 수 없어서 지난 통은 못 연다. 다만 프로그램 메모리 전체가 털리면 그 접속(세션)은 위험하다 — 과장하지 않는다.
  • 다시 접속하면 새 세션 키로 CK₁부터 새로 시작한다.
  • 문장 섞기("next" ‖ 평문)는 우리 팀이 넣은 변형이다. 표준 래칫(Signal의 대칭 래칫)은 평문을 섞지 않는다. 솔직히 보안상 이득은 거의 없다. 대신 한 통이라도 빠지면 그다음 열쇠를 만들 수 없어서, TCP라 빠질 일이 없다는 전제 위에 서 있다. 11-02 버전에 이미 들어가 테스트까지 통과했으니 그대로 쓴다.
  • 전체 대화는 지금처럼 사람마다 한 통씩 — 이제는 사람마다 다른 열쇠로 잠근 한 통씩이다. 16명이면 16번 잠근다.
  • 방장 방식에서도 같다. 방장은 다른 사람끼리의 글을 중계만 하고 열지 못한다. 방장 앞으로 온 글만 방장이 연다.

08받을 때 검사 순서

받은 통마다 이 순서로 본다. 하나라도 걸리면 화면에 경고를 띄우고 그 통은 버린다. 경고 문구는 11-02 버전 코드 그대로다.

  1. 이 사람과 열쇠가 있나? 없으면 [!] 열쇠를 모르는 ○○가 보낸 메시지 · 폐기
  2. seq가 이미 받은 번호 이하인가? → 다시 보내기 [!] 순서번호 불일치: ○○의 #5 메시지는 이미 받은 번호 (재전송 의심) · 폐기
  3. seq가 건너뛰었나? (마지막+1이 아님) → 빼먹기 [!] ○○→나 #6 메시지를 못 받아서 그 뒤로는 열 수 없습니다: 대화가 끊겼습니다. 다시 접속하세요
  4. 풀리나? 안 풀리면 → 바꾸기 [!] 변조 감지: ○○의 #6 메시지가 잠근 그대로가 아님 (중간에 바뀜) · 폐기. 열쇠는 앞으로 안 돌렸으니 진짜 6번이 오면 열린다 — 가짜 한 통으로 대화가 깨지지 않는다.
  5. 통과 → 열쇠를 한 칸 돌리고, 받은 번호를 적고, 화면에 띄운다.

중계가 보내는 SYS 알림("○○ 입장" 같은 것)은 잠그지 않는다. 그래서 암호화 뒤에는 명단을 도장이 맞는 HELLO로만 늘린다. 퇴장 알림은 그대로 믿는다 — 중계가 거짓 퇴장을 보내도 그 사람과 대화가 끊기는 것뿐이고, 몰래 읽히지는 않는다.

102인 잠금 — 두 열쇠 금고

민지가 비밀(예: 동아리 통장 비밀번호)을 금고에 넣고 현우와 수아 두 사람에게 맡긴다. 그 뒤로는 현우와 수아가 둘 다 동의해야만 열린다. 은행 금고의 열쇠 두 개, 핵 발사 열쇠 두 개와 같은 생각이다.

누가혼자 열 수 있나이유
현우못 엶자기 조각 S1만 있다
수아못 엶자기 조각 S2만 있다
중계 (서버·방장)못 엶조각이 현우·수아 신원 키로 봉해져 있다
민지 노트북못 엶맡기고 나면 열쇠와 조각을 지운다 (민지는 원래 내용을 안다)
현우 + 수아엶이게 목적. 수아가 승인하면 현우 화면에 뜬다

원리 — XOR로 반 나누기

XOR은 비트를 하나씩 비교해 같으면 0, 다르면 1. 비밀과 같은 길이의 완전한 무작위 값 S1을 뽑고, S2 = 비밀 ⊕ S1로 둔다. S1 ⊕ S2를 하면 비밀이 다시 나온다. S1은 그냥 무작위고 S2도 무작위처럼 보여서, 한 쪽만 봐서는 비밀에 대해 아무것도 알 수 없다. 직접 해 보기:

비밀 (바이트)
S1 — 현우 조각 (무작위)
S2 — 수아 조각 (비밀 ⊕ S1)
S1 ⊕ S2

실제로는 비밀을 직접 나누지 않는다. 무작위 잠금 열쇠 L(32바이트)로 비밀을 잠그고, 그 L을 위처럼 S1·S2로 나눈다. 비밀 길이와 상관없이 조각은 늘 32바이트다.

11금고 흐름

모든 화살표는 중계를 거친다. 중계는 받을 사람 칸만 보고 넘긴다. 중계가 아무것도 보관하지 않으니 맡길 때와 열 때 관련된 사람이 접속해 있어야 한다.

#누가 · 무엇을중계가 보는 것
1민지 — 잠금 열쇠 L로 내용 잠그기 → L = S1 ⊕ S2 → (S1 + 제목)을 현우 신원 키로, (S2 + 제목)을 수아 신원 키로 봉투에 넣기 → 묶음 전체에 도장 → 둘에게 한 통씩 보내고 L·S1·S2 지움암호문, 봉투 2개, 도장
2현우·수아 — 민지 도장 확인 → 자기 봉투만 열어 제목 확인 → 묶음을 ~/.deolmi/이름/vault/에 저장—
3현우 /open 제목 — 금고 번호에 도장 찍은 열람 요청을 수아에게금고 번호, 도장
4수아 — 현우 도장 확인 → 화면에 무엇을 누가 열려는지 뜸 → /approve → 자기 조각 S2를 현우만 열게 다시 봉하고, 열쇠 전달 증명에 도장 → 자기 사본 지움, 승인한 번호 기억현우만 여는 봉투, 도장

  • 봉투가 신원 키로 봉해져 있어서 다음 접속에도 열린다. 세션 키로 봉했다면 끄는 순간 못 열게 된다.
  • 한 번 열면 끝이다. 현우는 묶음을, 수아는 사본을 지운다.

14미리 막은 구멍

11-02 설계를 검토하면서 찾은 구멍과 막는 법이다. 코드를 옮길 때 이 줄을 빼먹으면 구멍이 다시 열린다.

심각도구멍막는 법
치명봉투는 보낸 사람이 익명이라, 중계가 "민지의 금고"를 위조할 수 있다민지가 신원 키로 묶음 전체(보유자 둘, 봉투 둘, 암호문, nonce)에 도장. 금고 번호도 묶음 해시
치명지문이 세션 키만 덮으면, 중계가 봉투용 공개키를 바꿔치기해 두 조각을 다 연다지문은 신원 키 하나만. 봉투 키는 신원 키에서 변환. 세션 키에는 신원 키 도장
높음숫자 12자리(40비트) 지문은 같은 지문이 나오는 키를 몇 시간이면 찾는다단어 8개(64비트)
중간제목 해시를 평문으로 보내면 중계가 "통장 비번" 같은 흔한 제목을 넣어 맞혀 본다제목은 봉투 안에만. 제목이 든 증명도 래칫으로 잠가 보냄
중간승인하는 사람이 무엇을 승인하는지 모르고, 요청·승인에 도장이 없다제목을 보유자 둘에게 봉해 보냄(길이 고정). 요청과 승인에 도장
참고풀기에 실패해도 래칫이 돌면 가짜 한 통으로 대화가 깨진다성공했을 때만 전진
참고중계가 예전 열람 요청을 다시 보낸다승인한 금고 번호를 기억해 두 번째는 거절
참고세션 키까지 신원 키에서 만들면 접속마다 같은 키가 나온다세션 키는 매번 새로, 신원 키로는 도장만

15못 막는 것

  • 누가 누구에게 언제, 얼마나 긴 글을 보내는지는 중계가 안다. 넘겨주려면 받을 사람 칸을 봐야 해서다.
  • 빼먹기·끊기 자체는 막지 못한다. 들킬 뿐이다. 중계가 다 버리면 대화가 안 된다.
  • 처음 만났을 때 단어를 안 맞춰 보면 중계가 그때부터 끼어들 수 있다. 그래서 확인 전에는 경고를 띄운다.
  • 내 노트북이 해킹되면 신원 키 파일과 화면이 다 털린다.
  • 금고에서 연 내용을 베껴 적거나 화면을 찍는 것. 증명할 수 있는 건 "수아가 현우에게 열쇠를 넘겼다"까지다.
  • 현우와 수아가 짜고 열면 열린다 — 그게 2인 잠금의 정의다. 맡긴 민지는 원래 내용을 안다.
  • 중계가 아무것도 보관하지 않으니, 맡길 때와 열 때 관련된 사람이 동시에 접속해 있어야 한다.
