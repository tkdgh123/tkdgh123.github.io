01준비 — 처음 한 번만

윈도우 — Visual Studio

무료인 Visual Studio Community를 깐다. 설치 화면의 "워크로드"에서 C++를 사용한 데스크톱 개발에 체크한다 (C 컴파일러 cl이 여기 들어 있다). 이미 깔려 있으면 이 단계는 건너뛴다.

빌드와 실행은 시작 메뉴의 Developer PowerShell for VS 창에서 한다. 보통 PowerShell 창에서는 cl을 못 찾는다.

리눅스 · WSL · 맥

# 우분투 (WSL이면 시작 메뉴의 "Ubuntu" 창) sudo apt update && sudo apt install -y build-essential # 맥 — 터미널에서 (맥에서는 아직 직접 돌려 보지 못했다) xcode-select --install

02코드 받기

deolmi.c 파일 하나가 프로그램 전부다. 코드가 바뀌면 같은 줄을 다시 치면 새것으로 덮어쓴다.

# 윈도우 — Developer PowerShell for VS cd ~\Downloads curl.exe -O https://tkdgh123.github.io/secure-msg/code/src/deolmi.c
# 리눅스 · WSL · 맥 cd ~ curl -O https://tkdgh123.github.io/secure-msg/code/src/deolmi.c

브라우저로 받아도 된다: deolmi.c 받기 — 윈도우 다운로드 폴더에 들어간다. WSL에서는 cd /mnt/c/Users/윈도우이름/Downloads 로 간다.

03빌드

# 윈도우 — deolmi.exe 가 생긴다 cl /utf-8 deolmi.c # /utf-8 을 빼면 화면의 한글이 깨진다
# 리눅스 · WSL · 맥 — deolmi 가 생긴다 gcc -o deolmi deolmi.c # 아무 말 없이 끝나면 성공

이제 윈도우는 .\deolmi, 리눅스·맥은 ./deolmi 로 켠다. 아래 예시는 윈도우 기준이다. 리눅스·맥이면 .\를 ./로 바꿔 치면 된다. 윈도우와 리눅스 노트북이 섞여 있어도 서로 대화된다. MSYS2·MinGW의 gcc를 쓰면 gcc -o deolmi.exe deolmi.c -lws2_32 (이 방법은 아직 직접 확인하지 못했다).

04혼자 먼저 해 보기 — 노트북 한 대

창을 두 개 연다. 하나는 방을 여는 방장, 하나는 들어오는 참가자. 같은 컴퓨터면 주소를 안 써도 된다.

# 창 1 — 방장 (방을 열고, 자기도 대화한다) .\deolmi 민지 --host # 창 2 — 참가자 .\deolmi 현우

Windows Terminal에서는 Alt+Shift+D 로 창을 나누면 한 화면에서 둘 다 보인다. 아무 글이나 치고 엔터를 누르면 상대 창에 뜬다.

05친구와 채팅 — 노트북 두 대

둘 다 같은 와이파이에 있어야 한다. 한 사람(방장)이 방을 열고, 친구가 그 노트북 주소로 들어온다. 방장이 곧 서버라서, 셋 이상이어도 똑같이 모두 방장 주소로 들어온다.

방장 노트북 — 처음 한 번만 할 일

윈도우에서 방을 열면 — 처음 --host로 켤 때 Windows 보안 경고(방화벽) 창이 뜬다. 개인 네트워크와 공용 네트워크를 둘 다 체크하고 액세스 허용을 누른다. 학교 와이파이나 핫스팟은 보통 "공용"이라서, 공용을 빼면 친구가 못 들어온다.

실수로 취소를 눌렀으면: 설정 → 개인 정보 및 보안 → Windows 보안 → 방화벽 및 네트워크 보호 → 방화벽에서 앱 허용 → deolmi 를 찾아 개인·공용을 켠다.

WSL(우분투) 안에서 방을 열면 — WSL은 기본 설정이면 바깥에서 들어오는 연결을 받지 못해서 두 가지를 해 둔다.

① 미러링 — 메모장으로 C:\Users\이름\.wslconfig 파일을 만들고 아래 두 줄을 넣는다. 저장한 다음 PowerShell에서 wsl --shutdown 하고 우분투를 다시 켠다. (윈도우 11 22H2 이상)

[wsl2] networkingMode=mirrored

② 방화벽 열기 — 관리자 PowerShell에서 한 번만 실행. 덜미가 쓰는 9000번 포트로 들어오는 연결을 허용한다.

New-NetFirewallHyperVRule -DisplayName "덜미 9000" -Direction Inbound ` -VMCreatorId "{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}" ` -Protocol TCP -LocalPorts 9000 -Action Allow

참가자 노트북은 01~03만 하면 된다.

채팅할 때마다

# 1. 방장 — 방 열기. 친구가 칠 명령이 주소까지 붙어서 뜬다 .\deolmi 민지 --host [주소] 192.168.0.5 — 다른 컴퓨터는 .\deolmi 이름 192.168.0.5 으로 들어와요 # 2. 친구 — 그 명령에서 "이름"만 자기 이름으로 바꿔 친다 (리눅스·맥이면 ./deolmi) .\deolmi 현우 192.168.0.5 # 3. 셋째, 넷째도 같은 주소로 (한 방에 16명까지) .\deolmi 수빈 192.168.0.5

실제로 돌려 본 화면

두 프로그램을 띄워 실제로 주고받은 화면이다 (주소만 예시로 바꿨고, /who 줄과 시작할 때 뜨는 사용법 설명은 줄였다). 민지> 로 시작하는 줄이 내가 친 것이다.

06대화 명령

치는 것하는 일
그냥 글방에 있는 모두에게
/dm 이름그 사람하고만 1:1. 프롬프트가 나→상대> 로 바뀐다
/all다시 모두에게
/who지금 들어와 있는 사람
/help · /quit명령 보기 · 나가기 (Ctrl+C 도 나가기)

방장이 나가면 방이 닫힌다. 방장은 남들끼리의 1:1도 중계하므로, 암호화 전인 지금은 방장 컴퓨터에서 내용을 볼 수 있다.

07막히면

  • 'cl'은(는) … 인식되지 않습니다 → 보통 PowerShell 창이다. 시작 메뉴의 Developer PowerShell for VS 를 연다. 그래도 없으면 01의 "C++를 사용한 데스크톱 개발"을 안 깐 것이다 (Visual Studio Installer → 수정).
  • 화면의 한글이 깨짐 → 빌드할 때 /utf-8 을 뺐다. cl /utf-8 deolmi.c 로 다시 빌드한다.
  • → 그 주소에 열린 방이 없어요 → 방장이 아직 안 켰거나 주소가 틀렸다. 방장을 먼저 켠다.
  • → 연결이 중간에서 막혔어요 (5초 기다린 뒤 뜸) → 방장 노트북의 방화벽을 확인한다 (05). 친구 윈도우 PowerShell에서 Test-NetConnection 192.168.0.5 -Port 9000 의 TcpTestSucceeded 가 True 여야 한다.
  • 그래도 안 됨 → 학교·카페 와이파이는 기기끼리 연결을 막는 경우가 많다. 한 사람 휴대폰 핫스팟에 둘 다 연결하고 방을 다시 연다. 바뀐 주소가 [주소] 줄에 뜬다.
  • bind: … 하나만 사용할 수 있습니다 (오류 10048) · bind: Address already in use → 이미 켜 둔 덜미가 있다. 그 창을 닫는다 (윈도우 taskkill /im deolmi.exe, 리눅스 pkill -x deolmi). WSL에서 방장을 막 껐다면 몇 초 뒤에 다시 연다.
  • 이름이 거절됨 → 이름은 한글 5글자(15바이트)까지, 띄어쓰기와 / 없이. 이미 들어와 있는 이름이나 방장 이름도 안 된다.
