덜미 · 실행과 구조

실행하기

빌드해서 서버와 클라이언트를 띄우는 법. 그리고 "서버와 클라이언트를 한 프로그램에서 함께 할 수 있나?"에 대한 답.

01처음 한 번 — 우분투 준비

윈도우라면 WSL2 위에서 돌린다. 평문 버전이라 libsodium도 필요 없다.

# 윈도우 PowerShell (관리자)에서 — 한 번만 wsl --install -d Ubuntu-24.04 # 재부팅하고 우분투를 처음 켜면 사용자 이름·비밀번호를 정한다. 그다음: sudo apt update && sudo apt install -y build-essential

02빌드

코드가 있는 폴더로 가서 make. 서버와 클라이언트 두 개가 만들어진다.

cd /mnt/c/Users/user/Desktop/deolmi # 코드 둔 곳 make gcc ... -o server ... gcc ... -o client ... make test # 네트워크·서버 테스트가 다 통과하면 OK
참고 — wsl --cd <경로> 가 에러나는 환경이 있다. 그럴 땐 wsl -d Ubuntu-24.04 -- bash -lc "cd /mnt/c/.../deolmi && make" 처럼 bash 안에서 cd 한다.

03한 대에서 여러 명 (제일 쉬움)

터미널을 여러 개 연다. 하나는 서버, 사람마다 하나씩 클라이언트. 같은 컴퓨터면 서버 주소는 생략(127.0.0.1).

# 1번 터미널 — 서버 ./server [서버] 9000번에서 기다리는 중 … # 2번 터미널 — 민지 ./client 민지 # 3번 터미널 — 현우 ./client 현우
  • 그냥 치면 전체 대화, /dm 이름 은 1:1, /who 는 접속자, /quit 로 나간다.
  • Windows Terminal이면 창 하나를 Alt+Shift+D 로 나눠 네 칸을 만들면 서버·세 명을 한 화면에서 본다.
  • 서버를 끄려면 그 터미널에서 Ctrl+C.

04여러 노트북에서 (발표용)

같은 와이파이의 노트북들이 붙으려면, 서버를 켤 노트북에서 두 가지가 돼 있어야 한다.

① 미러링

C:\Users\<이름>\.wslconfig 에 아래를 넣고, 바꿨으면 wsl --shutdown 후 다시 켠다. 이러면 WSL이 윈도우와 같은 LAN IP를 쓴다.

[wsl2] networkingMode=mirrored

② 방화벽 인바운드 9000 허용

WSL은 Hyper-V 방화벽 인바운드 기본값이 Block이라, 규칙을 안 넣으면 다른 노트북이 못 붙는다. 관리자 권한 PowerShell에서 한 번만:

New-NetFirewallHyperVRule -DisplayName "덜미 9000" -Direction Inbound ` -VMCreatorId "{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}" ` -Protocol TCP -LocalPorts 9000 -Action Allow

확인은 Test-NetConnection <서버 IP> -Port 9000 의 TcpTestSucceeded 가 True 면 열린 것. 서버 노트북의 IP는 ipconfig 의 Wi-Fi IPv4 주소. 다른 노트북은:

./client 수빈 192.168.0.5 # 뒤에 서버 노트북 IP

05막히면

  • bind: Address already in use → 서버가 이미 떠 있다. 이전 서버를 끄거나(pkill -x server) 잠깐 뒤 다시.
  • 다른 노트북이 안 붙음 → 위 방화벽 규칙 + 같은 와이파이 + IP 확인(Test-NetConnection).
  • 클라이언트가 바로 꺼짐 → 서버가 안 떠 있거나 주소가 틀림. 서버 먼저 켠다.
  • 이름이 거절됨 → 이름은 15바이트까지(한글 5글자), 띄어쓰기와 / 없이.

06서버와 클라이언트를 한 프로그램에서?

짧은 답: 된다. 지금 둘로 나눠 둔 건 어쩔 수 없어서가 아니라, 구조를 단순하게 두려고 일부러 그렇게 한 것이다.

지금은 가운데 서버 1개가 모두를 이어 주는 별 모양이다. 서버는 받은 메시지를 to에 적힌 사람에게 전해 주기만 한다. 합치는 길은 세 가지다.

방법 1한 파일, 켤 때 역할 선택쉬움

./deolmi --host 면 서버, ./deolmi 민지 면 클라이언트. net.c 같은 공통 코드를 함께 쓰고 main만 둘로 나눈다. 배포 파일이 하나가 된다. (동시에 두 역할은 아니고, 켤 때 고른다.)

방법 2호스트가 서버이면서 참여자중간

한 프로세스가 포트를 열어 중계도 하고, 자기도 방의 참가자로 대화한다. 서버 터미널을 따로 안 띄워도 된다. poll 하나로 (듣는 소켓 + 손님들 + 내 키보드)를 같이 보고, 내가 친 메시지는 네트워크를 거치지 않고 바로 중계 경로에 넣으면 된다.

방법 3서버 없이 완전 P2P큼

모두가 서로 직접 연결하는 그물망. 중앙 서버가 사라지지만, 누가 누구에게 잇고 그룹 대화를 누가 중계할지가 복잡해진다. 과제에는 과하다.

추천 — 지금은 역할을 나눠 두는 편이 낫다. ⑴ 구조가 단순해 디버깅과 발표 설명이 쉽고, ⑵ 나중에 암호화를 얹을 때 "서버는 내용을 못 보고 전해 주기만 한다"를 보여 주려면 서버가 뚜렷이 구분돼 있는 게 유리하다. 배포를 하나로 하고 싶으면 방법 1이 깔끔하고, 호스트도 대화에 끼고 싶으면 방법 2가 편의 업그레이드다.

실제로 만들어 봤어요 — deolmi (방법 2)

방법 2를 그대로 구현했다. 한 프로그램이 방장이면 중계와 대화를 함께 하고, 참가자는 방장 주소만 알면 된다. 별도 서버 프로세스가 없다 — 방장이 곧 서버다. 이름·전체 대화·/dm·/who·입퇴장까지 된다. (P2P 1:1 실험에서 막혔던 "셋째가 조용히 무시됨·메시지 쪼개짐"은 연결을 배열로 들고 net.c의 길이 구분을 써서 해결했다.)

# 방장 — 방을 연다 (중계하면서 자기도 대화) ./deolmi 방장 --host # 참가자 — 방장 주소만 알면 된다 (같은 컴퓨터면 주소 생략) ./deolmi 민지 192.168.0.5

코드는 deolmi.c 에서 볼 수 있다.

코드는 전체 코드에서, 원리와 계획은 덜미 설명서에서.
