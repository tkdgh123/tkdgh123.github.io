뼈대 넣기

뼈대는 부모-자식으로 이어진 나무입니다. 마네킹은 조각 하나가 뼈 하나를 통째로 따라가서, 사람 캐릭터에서 가장 어려운 단계를 건너뜁니다.

뼈대는 나무 모양

부모가 움직이면 자식이 따라옵니다. 어깨를 돌리면 팔·손이 같이 가요. 맨 위가 엉덩이(Hips)인 건 몸의 무게중심이라 이동의 기준이기 때문입니다.

알아야 할 말 여섯 개

휴식 자세 Rest pose

모든 회전값이 0인 기준 자세. 마디는 팔을 수평으로 편 T자 자세로 만듭니다. 기준이 맞아야 "팔 30° 올려"가 어느 몸에서나 같은 뜻이 돼요.

롤 Bone roll

뼈가 길이 방향으로 얼마나 비틀려 있는지의 기준. 엉망이면 무릎이 반대로 꺾이고 손목이 꼬입니다. 좌우가 대칭으로 굽는지로 확인.

FK Forward Kinematics

부모부터 차례로 각도를 줘서 자세를 만듦. 어깨 → 팔꿈치 → 손목. 휘두르기에 직관적이고, 마디의 첫 화면 걷기가 이 방식.

IK Inverse Kinematics

손끝·발끝 위치를 정하면 중간 관절 각도를 계산. 발을 계단에 붙일 때 씀. 무릎이 어느 쪽으로 꺾일지는 폴 타깃(pole)이 정함.

컨스트레인트 Constraint

뼈에 거는 규칙. 회전 제한(팔꿈치가 뒤로 안 꺾이게), 다른 뼈 따라 하기 등. Unity로는 안 넘어가서 내보낼 때 구워야(Bake) 함.

스키닝 · 웨이트 Skinning

피부의 점 하나하나가 어느 뼈를 얼마나 따라갈지 정하는 일. 팔꿈치 안쪽이 50:50이면 살이 부드럽게 접힘. 초보가 가장 많이 막히는 곳.

마네킹은 웨이트가 필요 없다

사람 캐릭터 (스킨)

피부 한 장이 여러 뼈에 나뉘어 붙음.

  • 관절에서 살이 접히는 걸 칠해서 맞춰야 함
  • 사탕 껍질처럼 비틀림, 어깨 부피 꺼짐
  • 점 하나가 엉뚱한 뼈를 따라가 튐

마디 마네킹 (강체)

조각 하나 = 뼈 하나, 100%.

  • 위팔 조각은 위팔 뼈만 따라감
  • 관절 공은 부모 쪽 뼈에 붙임. 돌아도 모양이 안 변해 티가 안 남
  • 스크립트로 자동화하기 쉬움

계획 변경

Mixamo에 마네킹을 올려 자동 리깅하지 않습니다. 뼈는 Blender 스크립트로 Mixamo 이름 그대로 직접 넣고, 동작은 Mixamo 기본 캐릭터로 받아 Unity가 마네킹에 옮겨 입힙니다.

Mixamo 자동 리거는 한 덩어리로 이어진 몸을 기준으로 해서, 관절 공 때문에 조각이 떨어진 마네킹은 거부되거나 살처럼 부드럽게 휘어 버릴 수 있음. 실제로 되는지는 0단계에서 한 번만 시험해 봅니다.

확인 문제

위팔 조각을 위팔 뼈에 100% 붙이면 웨이트 칠하기가 왜 필요 없나요?

모든 점이 뼈 하나만 그대로 따라가니, 두 뼈 사이에서 섞어 줄 부분이 없기 때문입니다. 강체라 통째로 움직이면 끝.

Unity에 넣은 모델이 회전 (-90, 0, 0), 크기 100으로 들어왔어요. 왜죠?

Blender(Z가 위)와 Unity(Y가 위)의 축·단위 차이에 크기·회전 적용을 안 한 게 겹친 것. Blender에서 Ctrl+A로 적용하고, 내보내기 배율·축 설정을 확인합니다.

Blender에서 IK로 발을 바닥에 붙였는데 Unity에선 발이 떠요.

FBX는 IK 규칙이 아니라 뼈의 위치·회전 키만 담습니다. 내보낼 때 Bake Animation을 켜서 결과를 키로 구워야 해요.

무엇이 움직임을 자연스럽게 만드나

애니메이션 원칙, 사람 걸음의 숫자, 게임 액션의 박자. 마디의 관찰 도구가 재는 기준이 여기서 나옵니다.

마네킹에 중요한 원칙 일곱 개 디즈니 12원칙 중

타이밍 · 간격timing · spacing

같은 20프레임이어도 프레임마다 손목이 움직인 간격이 일정하면 로봇, 처음·끝이 촘촘하고 가운데가 넓으면 힘이 실린 동작.

예비 동작anticipation

발차기 전에 무릎을 접고 몸을 뒤로 젖힘. 내려찍기 전에 두 팔을 머리 위에서 멈춤. "곧 온다"와 힘의 크기를 알려 줌.

따라오기 · 겹치기follow-through · overlap

몸통이 멈춰도 팔·머리·무기는 관성으로 더 감. 몸통 → 어깨 → 팔꿈치 → 손목 순서로 1~3프레임씩 늦게 출발하고 멈춤.

호arcs

관절은 회전이라 손끝·발끝은 거의 항상 곡선을 그림. 직선으로 꺾이면 기계 같음. 마디의 궤적 도구가 보는 것.

천천히 시작 · 천천히 끝slow in · slow out

시작과 끝은 느리고 가운데가 빠름. 일정한 속도(linear)는 기계 느낌.

무게weight

무거울수록 예비가 길고, 가속이 느리고, 멈출 때 눌렸다 올라오는 회복이 길다.

보조 동작secondary action

걸을 때 팔 흔들기, 머리 까딱임. 주 동작보다 눈에 띄면 안 됨.

걸음 한 주기

한 발이 땅에 닿은 순간부터 같은 발이 다시 닿을 때까지. 걷기는 사실 "넘어지다 다음 발로 받치기"의 반복입니다.

균형 — 무게중심과 발 사이 면

서 있을 때는 무게중심을 바닥에 내린 점이 두 발이 만드는 면 안에 있어야 합니다. 걷고 뛸 땐 일부러 밖으로 나갔다가 다음 발이 받쳐요. 그래서 "안쪽" 규칙은 멈춘 자세에서만 엄격합니다.

  • 한 발로 설 때 골반이 디딘 발 쪽으로 옮겨 가지 않으면 어색함
  • 한쪽 팔·다리를 뻗으면 반대쪽 몸통·엉덩이가 반대로 밀려 균형을 맞춰야 함
  • 가속할 땐 앞으로 기울어야 함. 내려찍은 뒤엔 체중이 앞발에 실려야 함

게임 액션의 박자

영화는 예비 동작이 길수록 좋지만, 게임은 버튼을 누르자마자 반응해야 합니다. 그래서 흔한 설계는 "시작은 짧게, 회복은 길게"입니다.

히트스톱 hitstop

맞는 순간 동작을 잠깐 멈춰 충격을 전달. 스매시 브라더스는 데미지에 비례해 늘리고 상한을 둠 (15% 기술 기준 얼티밋 15프레임, 상한 30). 사쿠라이는 "충격을 강조하는 시각 효과"라고 설명.

입력 버퍼 input buffer

동작이 끝나기 전에 미리 누른 입력을 기억. 스트리트 파이터 6은 대부분 4프레임 일찍 눌러도 받아 줌. 손맛이 좋아지는 숨은 장치.

캔슬 구간 cancel window

판정 뒤 일부 프레임부터 회피나 다음 공격으로 끊을 수 있는 구간. 회복이 길어도 답답하지 않게 해 줌.

읽히는 공격

사람이 화면을 보고 반응하는 데 약 0.2~0.25초(12~15프레임). 마디의 날아오는 공도 이보다 일찍 보여야 받아칠 수 있음. 추정

확인 문제

걷기에서 두 발이 모두 땅에 닿아 있는 시간은 한 주기의 약 몇 %? 달리기는?

약 20%. 달리기는 두 발 지지가 없고, 대신 두 발이 모두 공중에 뜨는 순간이 생깁니다.

30fps로 보통 걷기 한 주기는 대략 몇 프레임? 몸이 가장 높은 순간은?

약 30~36프레임. 가장 높은 건 한 발 위를 몸이 지나가는 순간(passing).

발차기가 굼떠서 예비 동작을 12 → 3프레임으로 줄였더니 힘이 없어 보여요. 반응은 지키면서 무게를 살리려면?

회복을 길게 하고 다리·몸통에 따라오는 동작을 넣기. 맞는 순간 히트스톱·카메라 흔들림·소리 더하기. 짧은 예비라도 첫 프레임부터 자세 변화를 크게 줘서 읽히게 하기.

마네킹을 만들 때 지킬 네 가지

  1. 단위는 미터, 배율 1. 키 1.8 m로 만들면 Unity에서 그대로 1:1.
  2. 늘렸으면 바로 적용. S로 늘린 뒤 Ctrl+A ▸ Scale. 안 하면 모서리 둥글리기가 찌그러지고 Unity 크기가 어긋남. 가장 흔한 사고.
  3. 매끈하게. 오른쪽 클릭 ▸ Shade Smooth. 모서리는 Bevel 모디파이어 0.01~0.02 m.
  4. 이름을 뼈와 맞추기. 조각 이름 = 붙을 뼈 이름. 스크립트가 짝을 찾기 쉬워지고 Unity에서도 그대로 보임.

발을 계단에 붙이기 (IK)

처음엔 패키지 없이 스크립트 하나(OnAnimatorIK)로 시작하고, 규칙이 여러 개 겹치면 Animation Rigging 패키지(1.3.1, Unity 6 지원)로 옮깁니다.

  1. Animator 레이어에서 IK Pass 켜기. 안 켜면 아무 일도 안 일어남 (가장 흔한 실수).
  2. 매 프레임 발 위 약 0.5 m에서 아래로 광선을 쏴 바닥을 찾음.
  3. 맞은 점 + 발목 높이를 발 목표 위치로, 바닥 기울기에 맞춰 발 회전.
  4. 발이 땅에 닿은 구간에서만 IK를 켜기. 흔드는 중엔 끔.
  5. 두 발 중 낮은 쪽만큼 엉덩이를 내려야 한쪽 다리가 쭉 펴져 뜨지 않음. 목표는 부드럽게 따라가게.

확인 문제

Mixamo 동작 10개를 쓰는데 동작마다 자세가 미묘하게 달라요.

각 동작 파일의 Rig를 Humanoid로 두고 Avatar를 "Copy From Other Avatar"로 마네킹 것을 지정. Configure에서 빨간 뼈(빠진 매핑)가 없는지 확인합니다.

OnAnimatorIK 코드를 썼는데 아무 일도 안 일어나요.

걸을 때 캐릭터가 두 배 속도로 앞으로 튀어 나가요.

동작 속 이동(Root Motion)과 코드 이동이 동시에 적용된 것. 제자리 동작으로 쓰거나 둘 중 하나만 씁니다.

예전 디아블로는 한 프레임짜리 원 하나로 피해를 줬지만, IV는 판정 영역을 여러 프레임에 걸쳐 움직여 눈에 보이는 이펙트와 맞춥니다. 휠윈드는 캐릭터를 따라 도는 부채꼴. 큰 이펙트는 궁극기에만 써서 화면이 읽히게 함.

발차기 판정을 발 궤적 따라 움직이는 캡슐로, 내려찍기는 퍼지는 원으로.

명조 작은 수치가 손맛을 만든다

개발팀이 직접 말한 건 "회전 각속도를 키워 지연감을 줄였다", "같은 동작도 메카에 쓰면 붕 떠 보여서 분사 날개로 납득시켰다", "강타 때 배경음을 낮춰 대비를 줬다". 저스트 회피·패링 수치는 공식 공개가 없음.

회전 속도·가속을 조절 가능한 값으로 빼 두고 직접 튜닝.

원신 만든 뒤 게임 안에서 검증

GDC 2021 발표: 캐릭터 모델이 완성되면 게임 디자인 부서와 이동·액션을 함께 설계하고, 반드시 실제 게임 환경에서 검증하며 조정. 마디와 같은 Unity를 깊게 개조해 씀. 동작 제작 방식은 공개 안 됨.

동작은 빈 화면이 아니라 계단·경사가 있는 실제 맵에서 확인.

젤다 야숨 · 왕눈 규칙이 몸짓이 된다

물리는 기성 엔진(Havok)에 맡기고 "재미있게 거짓말"을 얹음. 모든 벽을 오를 수 있게 하자 거대 보스 등반 같은 놀이가 생김. 애니메이터는 말 타기를 다가가는 방향마다 다르게 만드는 "상황 × 액션"으로 생각. 스태미나가 바닥나면 지친 공격 동작이 따로 있음(언론 보도).

같은 발차기도 서 있을 때·달릴 때·공중에서 변형을 준비.

공통으로 보이는 원칙

고치는 도구를 먼저

니어의 표시 도구, 디아블로의 지표, 고스트 오브 쓰시마의 데이터 밸런스. 마디의 관찰 도구가 같은 발상.

동작 위에 코드로 보정

포 아너의 발 IK, 파라곤의 보폭·경사 맞추기. 동작이 완벽하지 않아도 코드로 땅에 붙임.

출발·정지·방향 전환

걷기 자체보다 이 순간들이 느낌을 좌우함. 디아블로도 정지 동작을 따로 추가.

읽히는 게 먼저

디아블로의 화면 위계, 명조 보스의 예고 동작.

무게감은 한 단어로

갓 오브 워의 "땅에 붙은". 목표를 정하면 걷기부터 일관되게 맞출 수 있음.

혼자서 따라 할 순서 효과 ÷ 노력

  1. 프레임 데이터 + 애니메이션 이벤트. 시작·판정·회복·끊기 가능 구간을 숫자로 두고 화면에 막대로 표시. 니어 · 디아블로
  2. 판정을 동작에 맞춰 움직이기. 발 궤적을 따라가는 캡슐, 퍼지는 원. 디아블로
  3. 히트스톱 + 카메라 흔들림. 출발값은 0.05~0.08초, 아주 강한 공격만 0.1초 이상. 제3자 경험값
  4. 입력 버퍼 + 끊기 구간. 회복 끝 몇 프레임의 입력을 기억해 다음 동작으로.
  5. 출발·정지·방향 전환 동작 + 속도에 맞춘 보폭. 파라곤
  6. 발 IK. 계단에서 발 붙이기.
  7. 관찰 도구. 궤적, 관절 각도, 무게중심. 위 모든 조정의 눈.
  8. 회피·받아치기 창 + 성공 보상. 창 길이는 숫자로, 성공하면 짧은 슬로모션. 명조
  9. 회전 속도·가속을 조절 값으로. 명조
  10. 상황 × 액션 표. 같은 동작의 자세별 변형. 젤다

모션 매칭과 대규모 모션캡처는 1인 마네킹 프로젝트에 맞지 않아 목록 밖. 개념(앞으로 갈 길을 예측해 다음 자세 고르기)만 알아 둡니다.

확인 문제

포 아너의 모션 매칭은 어떤 세 가지를 비교해 다음 프레임을 고르나요?

현재 자세, 속도, 앞으로 갈 예상 경로.

디아블로 IV 공식 글에서 확인되는 타격감 기법은?

피해 판정 영역을 여러 프레임에 걸쳐 움직여 이펙트와 맞추고, 맞은 방향으로 래그돌에 힘을 줌.

"원신은 모션캡처로 만들었다"고 단정해도 되나요?

안 됩니다. 개발사가 밝힌 건 엔진(Unity 개조), 제작 흐름, 렌더링 정도이고 동작 제작 방식은 공개 자료가 없어요.

공 튕겨내기 미니게임의 손맛을 가장 먼저 다듬으려면 무엇부터 만들어야 하나요?

시작·판정·회복·끊기 구간을 프레임 수로 둔 프레임 데이터와, 그걸 화면에 보여 주는 표시. 니어 오토마타의 표시 도구와 같은 발상입니다.

공부해서 정한 것

기획서에 반영하고, 0단계부터 이대로 갑니다.

  1. Mixamo 자동 리깅 안 씀. Blender 스크립트로 Mixamo 이름 뼈를 직접 넣고, 동작만 Mixamo 기본 캐릭터로 받아 옮겨 입힘. 직접 시험 조각난 마네킹은 올라가긴 했지만 자동 리깅이 두 번 다 실패.
  2. Unity 뼈대는 Humanoid. 옮겨 입히기·발 IK·시선·관절 한계가 전부 여기서 됨. (Blender 조사의 Generic 권고는 이 기능들 때문에 채택 안 함)
  3. 조각은 정점 그룹 100%로 뼈에. 스크립트로 정확히 반복되고 사람형 몸으로 깔끔하게 들어감.
  4. Blender 5.2 LTS 고정. 5.3으로 안 갈아탐.
  5. 키프레임은 30 fps, Bezier. 동작 하나 = 액션 하나, Fake User 켬.
  6. FBX: Leaf Bones 끔, Bake 켬, All Actions 켬, NLA 끔, Apply Transform 끔. 큐브 → 액션 2개 → 마네킹 순서로 시험.
  7. 발 IK·시선은 OnAnimatorIK부터. 복잡해지면 Animation Rigging.
  8. Animator로 만듦. Unity 새 애니메이션 시스템은 기다리지 않음.
  9. 관찰 도구 기준값은 2장 표로 시작하고, 추정 표시된 값은 실제로 재서 고침.
  10. 공격은 프레임 데이터부터. 시작·판정·회복·끊기 구간을 숫자로 두고 화면에 표시. 판정은 동작을 따라 움직이게.
  11. 손맛 값은 전부 조절 가능하게. 히트스톱 길이, 회전 속도, 받아치기 창. 같은 동작도 서 있을 때·달릴 때·공중 변형을 표로.
